## Treasury

The root on-chain account for an AI agent. Derived as a PDA from `["treasury", owner, agentId]` on `aura-core`. Stores the agent's identity, full `PolicyConfig`, pause state, multisig config, swarm config, and protocol fee settings.

One owner can have multiple treasuries — one per unique `agentId`. Each treasury is independent unless joined to a swarm pool.

## Proposal

A request by the AI agent to execute a transaction. Submitted via `propose_transaction` (public) or `propose_confidential_transaction` (FHE path). A treasury stores a bounded pending queue with `MAX_PENDING_QUEUE_DEPTH = 3`; `PendingTransactionExists` (6004) is returned when that queue is full.

## PolicyConfig

The complete set of spending rules on a treasury. Two layers:

**Public rules** — evaluated locally by `aura-policy` in Rust. Stored in plaintext in `TreasuryAccount.policy_config`. Includes time windows, velocity, protocol allowlist, slippage, counterparty risk, recipient limits, anomaly detection, approval ladders, scoped pauses, and liveness requirements.

**Confidential counters** — `daily_limit_usd` and `per_tx_limit_usd` can be stored as `EUint64` FHE ciphertexts via `configure_confidential_guardrails`. When configured, these are evaluated by Ika Encrypt instead of locally.

Changing "dangerous" fields (raising limits, removing guardians) is subject to a timelock enforced by `TimelockNotElapsed` (6028).

---

## ViolationCode

A `u8` returned by the policy engine indicating why a proposal was rejected. `0` (`None`) means approved. There are 27 non-zero variants — see the [Policy Engine](/overview/policy-engine) page for the full table.

On-chain, the violation code is stored as an encrypted `EUint64` in the `policy_output_ciphertext` account for confidential proposals, then decrypted by `confirm_policy_decryption`.

---

## FHE (Fully Homomorphic Encryption)

A cryptographic technique that allows computation directly on encrypted data without decrypting it first. AURA uses FHE via the Ika Encrypt network (`4ebfzWdKnrnGseuQpezXdG8yCdHqwQ1SSBHD3bWArND8`) to evaluate whether a proposed spend would exceed the encrypted daily or per-tx limit.

The limit values are stored as `EUint64` ciphertexts. The FHE circuit compares them against the encrypted proposal amount and returns an encrypted `ViolationCode`. Only this small integer is decrypted on-chain — the limit values remain encrypted throughout.

## dWallet State

The treasury stores an inline `DWalletRecord` for each registered chain. Asset balances, per-wallet limits, status, reservations, labels, and authority rotation state live in the per-chain `DWalletAccount` sidecar at `["dwallet_state", treasury, chain_code]`. When a proposal is approved, `aura-core` CPIs into the Ika dWallet program (`87W54kGYFQ1rgWqMeu4XTPHWXWmXSQCcjm8vCTfiq1oY`) via `execute_pending` to request a co-signature. The agent receives the signed transaction bytes — never the private key.

The `MessageApproval` PDA is derived on the dWallet program using the curve code, public key bytes, signature scheme code, and message digest as seeds.

## Operator Role

A delegated maintenance grant stored in an `OperatorRole` PDA (`["operator_role", treasury, operator]`). Roles carry a `permission_mask` and an `expires_at` timestamp. Current operator-gated surfaces include address-list management, scoped pauses, policy simulations, liveness refreshes, snapshots, and health refreshes. Live signing/decryption instructions (`execute_pending`, `finalize_execution`, `request_policy_decryption`, `confirm_policy_decryption`) still require the treasury owner or AI authority.

Errors: `OperatorRoleMissing` (6044), `OperatorRoleExpired` (6045).

---

## Session Key

A short-lived signing key issued to the AI agent via `issue_session_key`. Stored in a `SessionKeyAccount` PDA. Scoped to a `max_amount_usd`, an `allowed_chains_bitmap`, and an `expires_at` timestamp. Reduces the need for the owner's keypair to be online for every proposal.

Errors: `SessionKeyInactive` (6037), `SessionKeyScopeViolation` (6038).

---

## Guardian / Multisig

An emergency authorization mechanism configured via `configure_multisig`. Stores a list of guardian public keys and a `required_signatures` threshold in `TreasuryAccount.multisig_config`. Guardians can satisfy guardian/multisig approval levels on already-approved proposals, veto staged config changes, rotate guardian sets, participate in ownership handover, and support emergency recovery flows. They do not convert a denied policy decision into an executable proposal.

Errors: `UnauthorizedGuardian` (6002), `InvalidGuardianConfiguration` (6027).

---

## Swarm Pool

A shared spending pool across multiple agent treasuries. Configured via `configure_swarm` and `init_swarm_pool`. Each member's proposal is checked against both its own limits and the shared pool counter (`shared_pool_limit_usd`). Violation: `SharedPoolLimit`.

---

## Budget Envelope

A scoped sub-budget attached to a treasury via `configure_budget_envelope`. Envelopes can be scoped by chain, category, or protocol. Each envelope has its own daily and weekly cap. Violations: `BudgetEnvelopeDailyLimit`, `BudgetEnvelopeWeeklyLimit`.

---

## Exposure Group

A cross-treasury aggregate cap. Multiple treasuries can join an exposure group (`join_exposure_group`). The group tracks total spend across all members. Violation: `ExposureGroupLimitExceeded`.

---

## External Liveness

A freshness record (`ExternalLiveness` PDA) that tracks whether external dependencies (Encrypt network, dWallet network, balance oracle, compliance oracle) have been recently confirmed. Configured via `init_external_liveness` and refreshed via `refresh_external_liveness`. Required when `LivenessConfig.require_*_freshness` flags are set. Violation: `ExternalDependencyStale`.

---

## Health Score

A computed `u8` score (0–100) stored in a `HealthScore` PDA. Initialized via `init_health_score`, refreshed via `refresh_health_score`. Used by `take_snapshot` to record point-in-time treasury health.

---

## Trust Tier

A trust classification (0–3) stored in `TrustIdentityAccount` that classifies agent behavior:

- **0 - Trusted**: Normal operation, 1.0× multiplier
- **1 - Watch**: Elevated caution, `watch_multiplier_bps` haircut
- **2 - Restricted**: Heavily restricted, `restricted_multiplier_bps` haircut + forced multisig approval
- **3 - Lockdown**: Proposal path blocked when the trust account is supplied

Secondary-agent capability breaches add to `threat_score`, clean activity decays it, and `restore_trust` lets the owner step the tier down manually.

---

## Scheduled Intent

A `ScheduledIntent` PDA that represents a recurring transaction pattern with budget controls. It becomes executable when `Clock::unix_timestamp >= next_run_at`; `execute_scheduled_intent` is permissionless when no keeper is configured and restricted to `keeper` when one is set.

- **Recurrence**: fixed `interval_secs` cadence with `start_at`, optional `end_at`, optional `max_runs`, `catch_up`, and `skip_on_deny`
- **Budget**: per-run cap and total lifetime cap
- **Conditions**: price-above/below, time-window, balance-above/below, and oracle-flag predicates

Violations: `ScheduledIntentBudgetExceeded`, `ScheduledIntentExpired`.

---

## Conditional Proposal

A proposal parked behind runtime conditions (`ConditionalProposal` PDA). Promoted into the pending queue via `try_trigger` when:

- Price oracle crosses threshold
- Time window opens
- Treasury balance meets minimum
- Custom oracle flag is set

Avoids occupying the pending slot until conditions are satisfied.

---

## Fee Vault

A `FeeVault` PDA storing prepaid fee balance and accrued protocol fees. The current on-chain charging path accrues an execution fee during successful `finalize_execution` when a `FeeVault` is supplied. Creation, subscription, and AUM fee fields are stored in fee schedules/templates for billing policy, but proposal submission does not charge the vault.

Fees can be split across up to 4 protocol, integrator, referral, or guardian recipients via a `FeeSplit` table.

---

## Billing Template

A reusable `FeeSchedule` definition that can be applied to multiple treasuries. Built-in profile kinds:

- **Payroll**
- **TradingDesk**
- **DaoTreasury**
- **GrantProgram**
- **VendorPayments**
- **ColdStorage**
- **Specialty**

Templates can be forked and parameterized with overrides.

| Budget envelope | `["budget_envelope", treasury, envelopeId_le64]` | Scoped sub-budget |
| Exposure group | `["exposure_group", authority, groupId_16bytes]` | Cross-treasury cap |
| Operator role | `["operator_role", treasury, operator]` | Delegated maintenance permissions |
| External liveness | `["external_liveness", treasury]` | Freshness record |
| Policy attestation | `["policy_attestation", treasury, attester, policyVersion_le64]` | Signed policy hash |
| Batch proposal | `["batch_proposal", treasury, batchId_le64]` | Batch result |
| Invariant report | `["invariant_report", treasury, reportId_le64]` | Invariant check result |
| Trust identity | `["trust_identity", treasury]` | Trust tier and history |
| Scheduled intent | `["scheduled_intent", treasury, intentId_le64]` | Recurring transaction |
| Conditional proposal | `["conditional_proposal", treasury, proposalId_le64]` | Trigger-based proposal |
| Fee vault | `["fee_vault", treasury]` | Prepaid + accrued fees |
