Every in-treasury instruction follows the same shape: load the `AgentTreasury` domain from its account,
mutate it (recording an audit event), then serialize it back and emit events. Standalone PDAs (fee vault,
swarm pool, operator role, …) follow an `init` / edit / `close` pattern. Instructions tagged <New /> were
added in the latest update and may not yet have typed SDK wrappers.

<Callout title="Gating">
  Unless noted, instructions are **owner-gated**. Some accept an **operator role** with the matching
  permission, the **AI authority** (proposals/session keys), or a **guardian quorum** (governance/recovery).
</Callout>

## Treasury lifecycle

| Instruction | Description | |
|---|---|---|
| `create_treasury` | Create the treasury PDA with an initial policy + fee schedule. | |
| `update_treasury_metadata` | Edit mutable settings (pending-tx TTL, high-risk threshold/guardian, sanctions toggle) in place. | <New /> |
| `migrate_treasury` | Realloc + advance the account to the current schema version. | |
| `transition_agent_state` | Move the agent between lifecycle states. | |
| `pause_execution` | Pause / resume all execution. | |
| `emergency_shutdown` | Halt the treasury and record a recovery pubkey. | |
| `trigger_dead_mans_switch` | Fire the inactivity switch after the threshold elapses. | |

|---|---|---|
