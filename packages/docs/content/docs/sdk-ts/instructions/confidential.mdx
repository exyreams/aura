Confidential guardrails store spending limits as FHE ciphertexts on-chain.
Policy evaluation happens over encrypted values — limits are never revealed,
preventing MEV exploitation.

Vector guardrails use the current split lifecycle: proposal persistence happens
first, and `executePendingVectorFhe` runs the compact Encrypt graph in a second
transaction. This avoids sharing the proposal instruction's BPF heap with the
vector graph CPI.

## configureConfidentialGuardrails

Configure scalar FHE guardrails — three separate `EUint64` ciphertext accounts
for the daily limit, per-tx limit, and spent-today counter.

```typescript
// Build only
const instruction = await client.configureConfidentialGuardrailsInstruction(
  accounts: ConfigureConfidentialGuardrailsAccounts,
  now: BNish,
);

// Build + send
await client.configureConfidentialGuardrails(
  owner: Signer,
  accounts: ConfigureConfidentialGuardrailsAccounts,
  now: BNish,
);
```

### Accounts

```typescript
interface ConfigureConfidentialGuardrailsAccounts {
  // From OwnerTreasuryAccounts:
  owner: PublicKey;
  treasury: PublicKey;
  // Own fields:
  dailyLimitCiphertext: PublicKey;
  perTxLimitCiphertext: PublicKey;
  spentTodayCiphertext: PublicKey;
}
```

### Example

```typescript
import BN from 'bn.js';

const now = new BN(Math.floor(Date.now() / 1000));

await client.configureConfidentialGuardrails(
  owner,
  {
    owner: owner.publicKey,
    treasury: treasuryPDA,
    dailyLimitCiphertext: dailyLimitCiphertextPDA,
    perTxLimitCiphertext: perTxLimitCiphertextPDA,
    spentTodayCiphertext: spentTodayCiphertextPDA,
  },
  now,
);
```

## configureConfidentialVectorGuardrails

Configure vector FHE guardrails — remaining daily limit, per-transaction limit,
and spent-today packed into a single `EUint64Vector` ciphertext.

```typescript
// Build only
const instruction = await client.configureConfidentialVectorGuardrailsInstruction(
  accounts: ConfigureConfidentialVectorGuardrailsAccounts,
  now: BNish,
);

// Build + send
await client.configureConfidentialVectorGuardrails(
  owner: Signer,
  accounts: ConfigureConfidentialVectorGuardrailsAccounts,
  now: BNish,
);
```

### Accounts

```typescript
interface ConfigureConfidentialVectorGuardrailsAccounts {
  // From OwnerTreasuryAccounts:
  owner: PublicKey;
  treasury: PublicKey;
  // Own field:
  guardrailVectorCiphertext: PublicKey;
}
```

### Example

```typescript
await client.configureConfidentialVectorGuardrails(
  owner,
  {
    owner: owner.publicKey,
    treasury: treasuryPDA,
    guardrailVectorCiphertext: guardrailVectorCiphertextPDA,
  },
  new BN(Math.floor(Date.now() / 1000)),
);
```

## Scalar vs Vector

| | Scalar | Vector |
|---|---|---|
| Ciphertext accounts | 3 (daily, per-tx, spent-today) | 1 (packed vector) |
| Update individual limits | Yes | No — replace all |
| Proposal execution | Single proposal CPI | Proposal tx + `executePendingVectorFhe` tx |
| Best for | Frequent limit updates | Stable configurations |

After guardrails are configured, use `proposeConfidentialTransaction` or
`proposeConfidentialVectorTransaction` to submit proposals over encrypted values.

Vector proposal helpers must create these `EUint64Vector` inputs off-chain via
Encrypt gRPC:

| Vector | Lanes |
| --- | --- |
| Guardrail state | `[remainingDailyLimit, perTxLimit, spentToday]` |
| Spend delta | `[-amount mod u64, 0, amount]` |
| Comparison | `[amount, amount]` |
| Flag indices | `[3, 4, 5, ...]` |
| Policy output | pre-allocated zero `EUint64Vector` |
