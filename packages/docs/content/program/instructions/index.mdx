Most in-treasury instructions follow the same shape: load the `AgentTreasury` domain from its account,
mutate it (recording an audit event), then serialize it back and emit events. Live CPI and settlement paths
sometimes mutate only the hot pending fields to stay within SBF limits. Standalone PDAs (fee vault,
swarm pool, operator role, …) follow an `init` / edit / `close` pattern.

<Callout title="Gating">
  Unless noted, instructions are **owner-gated**. Some accept an **operator role** with the matching
  permission, the **AI authority** (proposals/session keys), or a **guardian quorum** (governance/recovery).
</Callout>
